# Daats Website Loader And Card Polish Design

Date: 2026-07-13

## Goal

Add a demo-quality first-visit loading experience and tighten several shared presentation details on the Daats website without introducing page-specific hacks.

## Scope

In scope:

- Add a first-visit-per-session preloader that allows the site to finish loading behind a full-screen branded animation.
- Use the real transparent Daats logo mark already used in the header and footer.
- Show visible loading percentage during the preloader.
- Normalize paragraph-to-card spacing for sections that use intro copy followed by card grids.
- Give the homepage `Why shippers stay with Daats` feature cards the same hover/lift/maroon-outline language used by the site's other cards.
- Confirm the same hover treatment is applied consistently across other card-based sections.
- Increase the `Ready to move` CTA section height enough to avoid the truck roof feeling cut off.
- Restyle the footer `SERVICE WITH INTEGRITY` line to visually match the `COMPANIES` word in the Daats lockup, with a slightly larger size.

Out of scope:

- Redesigning the site's overall layout, typography system, or color palette.
- Changing marketing copy beyond structural placement required by the loader.
- Adding a loader to every navigation event in a way that delays normal browsing after the first page view.

## Existing Context

- The site is generated by `scripts/build-site.mjs`.
- Shared presentation is controlled through `assets/site.css`.
- Shared client behavior is controlled through `assets/site.js`.
- Generated HTML pages should continue to be produced from the generator rather than hand-patched.
- This workspace is not a git repository, so the spec can be written locally but cannot be committed here unless version control is initialized later.

## User-Approved Direction

### Loader

- Show the loader only on the first page visit in a browser session.
- Bias toward a dramatic demo feel rather than the fastest possible dismissal.
- Use the `Signal Pulse` motion language.
- Use the real transparent Daats logo mark in the center.
- Animate the mark with the approved `Breathing Mark` behavior.
- Place the `DAATS / COMPANIES` lockup above the mark.
- Place the loading percentage below the mark and closer to the center element than in the initial mockups.
- Use a black background while the animation plays.
- Allow the page to continue loading in the background.

### Shared UI polish

- Add more breathing room between intro paragraphs and the card groups that follow them.
- Apply that spacing consistently anywhere the site uses the same pattern.
- Make the `Why shippers stay with Daats` items behave like cards on hover and focus:
  - lift slightly from the page
  - gain the maroon outline/glow treatment
  - feel visually aligned with other site cards
- Review other card sections and keep the hover treatment consistent.

### CTA and footer

- Increase CTA section height enough that the truck roof no longer feels cut off.
- Apply the `COMPANIES` visual style to footer `SERVICE WITH INTEGRITY`.
- Make `SERVICE WITH INTEGRITY` slightly larger than the current logo's `COMPANIES` word.

## Implementation Design

### 1. Preloader architecture

The preloader should be injected into the shared page shell so it is available on all generated pages without duplicating markup manually in each file. It should be rendered near the top of `body` output in the generator and controlled by shared JavaScript.

Core behavior:

- On first page visit in the current browser session, show a full-viewport overlay.
- Use `sessionStorage` to remember that the loader has already been shown.
- Keep the page rendered behind the overlay so assets continue loading normally.
- Track progress using a staged, perception-driven counter rather than trying to measure every asset perfectly.
- Keep the loader visible for a minimum of about 1.8 seconds so the reveal reads as intentional during the demo.
- Gate dismissal on both:
  - a minimum dramatic runtime
  - the page reaching a ready state suitable for reveal
- On completion, animate the overlay out and remove or hide it so normal interaction resumes.

Why a staged counter:

- Static HTML pages do not provide a reliable "real" asset-by-asset loading percentage across all browser states.
- For a demo loader, perceived progress is more important than exact byte-level progress.
- A staged counter tied to readiness milestones will look intentional and avoid stalling at arbitrary values.

Suggested readiness model:

- Start near `0%` immediately.
- Progress smoothly through early values while the document parses.
- Accelerate through the mid-range while the page and hero media finish settling.
- Hold the final few percent until both the minimum runtime and `window.load` or equivalent readiness criteria are satisfied.
- Complete to `100%`, briefly resolve the full lockup state, then fade or slide the overlay away.

### 2. Preloader visual design

The loader should feel premium, minimal, and brand-led rather than flashy.

Visual structure:

- solid black background
- central real Daats transparent logo mark
- pulse-ring atmosphere around the mark
- `DAATS` with `COMPANIES` above the mark
- loading percentage below the mark, positioned closer to the mark than in the early mockups

Motion language:

- the logo mark uses a subtle breathing scale and opacity animation
- surrounding pulse rings move independently to create cinematic depth
- percentage can softly pulse or update with understated motion
- exit transition should be crisp and short, not slow or foggy

Accessibility:

- respect `prefers-reduced-motion` by reducing breathing and ring intensity and simplifying transitions
- ensure the overlay does not trap keyboard focus unnecessarily
- avoid announcing percentage changes aggressively to screen readers unless a minimal accessible status region is clearly useful

### 3. Shared spacing normalization

Spacing between section copy and card groups should be normalized through shared selectors instead of ad hoc margin edits.

Expected pattern:

- sections with `.section-copy` followed by `.card-grid`, `.blog-grid`, or similar card containers should have a consistent top gap
- sections using `.section-head` already have structured spacing; plain `.section-copy` sections need the missing shared margin

Design approach:

- define shared top spacing for card groups that immediately follow section intro copy
- avoid affecting non-card content such as split layouts, diesel table sections, or article bodies
- keep the change broad enough to cover existing repeated card layouts across home and internal pages

### 4. Feature-card hover unification

The homepage `feature-item` rows currently behave differently from the site's card components. They should be upgraded into card-like interactive panels while preserving the two-column layout and current content structure.

Expected hover and focus behavior:

- visible maroon outline and glow
- slightly darker background on hover and focus
- slight lift from the page
- same transition timing family as other cards

Implementation approach:

- update `.feature-grid` spacing as needed to support card presentation
- convert `.feature-item` from divider rows into bordered panel blocks
- preserve responsive behavior and readability
- include `:focus-within` behavior so keyboard users get the same affordance

Audit target:

- `.service-card`
- `.blog-card`
- `.credential-card`
- any other shared card class already intended to elevate on hover
- `.feature-item` after conversion

The goal is not to force every component into identical geometry, but to keep a coherent hover language across all card-like surfaces.

### 5. CTA height adjustment

The CTA band should gain enough vertical room to stop cropping pressure on the truck image.

Implementation approach:

- increase `.cta-band` minimum height
- increase `.cta-content` minimum height to match
- avoid changing overlay composition or button layout unless necessary
- preserve mobile layout and avoid introducing excessive empty space on small screens

### 6. Footer tagline typography

`SERVICE WITH INTEGRITY` should visually inherit from the lockup's `COMPANIES` style rather than the generic footer-bottom monospace styling.

Implementation approach:

- wrap or target the tagline separately in generated footer markup
- apply uppercase compact tracking consistent with `.brand-text small`
- increase font size slightly above the current `COMPANIES` size
- keep contrast and spacing appropriate for the footer-bottom row

This should remain subtle and brand-consistent, not oversized.

## Risks And Mitigations

### Risk: loader feels fake or stalls awkwardly

Mitigation:

- use milestone-driven progress with capped holds only near completion
- keep the total runtime short enough to feel intentional, not obstructive

### Risk: first-visit loader blocks interaction too long

Mitigation:

- store session flag after first successful reveal
- only show once per browser session

### Risk: spacing rules hit unintended sections

Mitigation:

- target card-following patterns specifically rather than broad paragraph margins
- verify on home and internal pages

### Risk: converting feature rows into cards breaks mobile layout

Mitigation:

- preserve existing grid breakpoints and test narrow layouts after the CSS change

## Success Criteria

- The first page visit in a session shows the approved branded loader.
- The loader uses the real Daats mark with the breathing animation, top lockup, and nearby percentage.
- The rest of the site loads behind the overlay and is ready when the loader exits.
- Card sections have improved spacing after intro paragraphs.
- `Why shippers stay with Daats` now uses the same hover language as the site's other card surfaces.
- The CTA truck no longer feels top-cropped.
- The footer tagline visually matches the requested lockup style.
